# Збірка та запуск

## Збірка STM32

Потрібні CMake ≥3.22, Ninja та Arm GNU Toolchain. `arm-none-eabi-gcc`
і решта інструментів toolchain мають бути в PATH. HAL, CMSIS, FreeRTOS
та RTT вже включені в проєкт.

Із кореня репозиторію:

```sh
cd firmware/vehicle-ecu
cmake --preset Debug
cmake --build --preset Debug
```

Для Release:

```sh
cmake --preset Release
cmake --build --preset Release
```

Результати: `build/Debug/vehicle-ecu.elf` і `build/Release/vehicle-ecu.elf`.
Прошивати відповідний ELF через ST-Link. Не використовувати повне
стирання Flash: останні 4 КБ містять калібрування й виключені з ELF.
Перед оновленням потрібна резервна копія цих даних, якщо їх важливо зберегти.

## Збірка й запуск Gateway

Встановити ESP-IDF 6.0.1 та інструменти ESP32-S3, активувати його
середовище (`export.sh` або ESP-IDF Terminal). Із кореня репозиторію:

```sh
cd firmware/remote-gateway
idf.py set-target esp32s3
idf.py build
idf.py -p PORT flash monitor
```

Замінити `PORT` на порт своєї плати. За потреби змінити GPIO та параметри
приймання в `idf.py menuconfig` → `Remote Gateway ELRS` / `PWM RC` / `UART`.
Збережені початкові параметри містяться в `sdkconfig.defaults` і Kconfig
компонентів. UART-консоль Gateway показує активне джерело ELRS/PWM/NONE.

## Запуск ECU та RTT

1. Виконати підключення за [hardware.md](hardware.md).
2. Для запуску на стенді підняти колеса та встановити стіки в нейтраль.
3. Увімкнути логіку, приймач і пульт. Стан RC=OK означає отримання
   валідних команд.

Для RTT потрібні ST-Link і OpenOCD із підтримкою `stm32g4x` та RTT.
Із кореня репозиторію:

```sh
openocd -f firmware/vehicle-ecu/tools/rtt-console.cfg
```

В іншому терміналі:

```sh
nc 127.0.0.1 9090
```

Конфіг консолі приєднується без reset/halt/resume та зберігає поточний
стан MCU. RTT працює лише на вивід, команд із ПК немає.

Формат рядка STAT:

```text
[12500] STAT RC=OK M=1 | DRIVE TRACK v=3.9kmh target=4.0kmh pwm=28% | STEER MANUAL pos=0/1000 pwm=0%
```

STAT формується кожні 500 мс. RC-переходи, FLT, калібрування та
STEER_RELEASE — окремі події; UART/feedback-зведення перевіряються раз
на секунду. Час у дужках — HAL uptime на момент публікації повідомлення.
Недоступні покази — `--`, повний стік режиму 3 — `target=MAX`.

Повна Log Queue або RTT up-буфер можуть відкинути діагностику без
очікування. Це не змінює дозволи моторів. Детального режиму та
лічильників втрат логування немає.

## Налаштування та калібрування

Параметри ECU: `firmware/vehicle-ecu/Core/Inc/*_config.h`.
Калібрування керма виконується фізично пультом і кнопкою:

1. За нейтральних стіків і придатного MT6701 утримувати PC13 3 с.
   Задні двигуни вимкнені; steering jog обмежений 15%.
2. Підвести кермо до фізичного центру. Відпустити стік, дочекатися
   спокою щонайменше 100 мс, коротко натиснути PC13.
3. Аналогічно підтвердити ліву, потім праву точку. Після правої точки
   виконується запис Flash з усіма вимкненими виходами.
4. Відпустити обидва стіки для повернення до звичайного керування.

LED: групи 1/2/3 спалахів — центр/ліва/права точка; суцільне світло
2 с — збережено; швидке блимання — відхилена дія або помилка.
Утримання PC13 3 с у сервісі скасовує процедуру без збереження.
