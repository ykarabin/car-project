# RTOS, UART-транспорт і RTT

Огляд задач — [architecture.md](../architecture.md#задачі-та-синхронізація).
Тут — обґрунтування й деталі.

## Задачі ECU

| Задача | Пріоритет | Стек | Робота |
| --- | --- | --- | --- |
| `defaultTask` | 24 | статичні 4096 Б | цикл 1 мс (`vTaskDelayUntil`): пульт, енкодери, регулятори, калібрування, FLT, IWDG |
| `rttLog` | 1 | статичні 4096 Б | форматування й вивід RTT; блокується на черзі |

`defaultTask` створює CMSIS-RTOS2 (у `.ioc` — Static), `rttLog` —
`xTaskCreateStatic` у `vehicle_log_start` з USER CODE RTOS_THREADS. Heap
FreeRTOS 16 КБ лишається для інших об'єктів. Мінімум вільного стеку на
стенді: 3304 і 3056 Б.

**Чому без mutex.** Моторами, регуляторами, калібруванням, LED і Flash
володіє лише `defaultTask`; FLT ISR може лише вимкнути виходи. Логер отримує
копії значень і час події, не читає живий стан і не підживлює IWDG. Рядкові
вказівники в повідомленнях — тільки на незмінні літерали. Дані ISR ↔ задача
читаються короткими PRIMASK-секціями зі збереженням попереднього стану.

`vTaskDelayUntil` задає бажаний розклад, а не гарантію: ISR, критичні
секції ядра й Flash можуть затримати цикл. Регулятори тому рахують
фактичний elapsed. Джитер і CPU load не виміряні.

## UART Gateway → ECU

- USART2 RX у перериванні; парсер `remote_parser_push` працює в ISR.
- Статичний FIFO на 8 подій `command / received_at_ms / valid`; valid і
  invalid не перезаписують одна одну.
- Задача читає до 9 подій за прохід (FIFO + подія переповнення).
- При переповненні фіксується час **першої** втрати; нові події відкидаються,
  доки префікс не прочитано, потім задача отримує invalid з цим часом.
  Так пізня добра команда не приховує втрату.
- ISR переозброює RX після кожного байта чи помилки; задача відновлює
  приймач, лише якщо ISR не зміг, під PRIMASK.
- Прапорці ORE / FE / NE / PE знімаються в USER CODE до їх очищення HAL.

На стенді періодично з'являються NE (шум). Пошкоджені рядки відкидаються,
а допуск 60 мс у `remote_command_monitor` не дає їм обривати рух.

## RTT

Один up-канал 2 КБ, без down-каналів, режим NO_BLOCK_SKIP: при повному
буфері повідомлення пропускається без очікування. Черга логів — 16
повідомлень, запис з wait = 0, при заповненні нове відкидається.
Лічильників втрат немає: RTT — діагностика, не журнал подій.

Кожні 500 мс — рядок стану, решта — події:

```text
[12500] STAT RC=OK M=1 | DRIVE TRACK v=3.9kmh target=4.0kmh pwm=28% | STEER MANUAL pos=0/1000 pwm=0%
[13500] STAT RC=OK M=1 | MOTOR BLOCKED fault=0x01
[14020] EVENT RC STALE
[15000] WARN UART hal=1 ne=1 ore=0 fe=0 pe=0 invalid=1 gap=0 rearm=0 fifo_lost=0
[17500] EVENT STEER_RELEASE CENTERED
[20000] PERF loop avg=12us max=41us jitter=7us cpu=3.5% loops=5000
```

- `[…]` — HAL uptime у мс на момент події (wrap uint32).
- `M` — режим 1 / 2 / 3; `target=MAX` — повний PWM режиму 3.
- `pwm` — знаковий запит регулятора, не вимір; `--` — непридатне значення.
- `STEER`: OFF, MANUAL, CENTER, MOVE, HOLD, STALLED, WAIT_NEUTRAL.
- `PERF` (раз на 5 с, за це вікно): `loop` — час одного проходу `defaultTask`
  від пробудження до блокування, середній і максимальний; `jitter` —
  найбільше відхилення періоду між проходами від 1 мс; `cpu` — частка часу
  поза idle-задачею; `loops` — кількість проходів (≈ 5000).
- `fault` — маска FLT: LEFT = 1, RIGHT = 2, STEERING = 4.
- UART і FEEDBACK перевіряються раз на секунду й друкуються лише при змінах.

Підключення консолі — [usage.md](../usage.md#запуск-ecu-та-rtt).

## Вимірювання продуктивності

Лічильник тактів DWT CYCCNT (170 МГц, переповнення раз на 25 с — вікно 5 с
коротше). `cpu_stats.c` — чиста логіка з хостовими тестами, `cpu_cycles.c` —
доступ до DWT і облік часу idle-задачі. Idle рахують трасувальні макроси
`traceTASK_SWITCHED_IN/OUT` у `FreeRTOSConfig.h` (секція USER CODE, переживає
перегенерацію CubeMX).

Ціна: одне читання регістра на початку й у кінці кожного проходу та два
короткі виклики на кожне перемикання задач — десятки тактів на мілісекунду,
за оцінкою менше 0,1 % CPU (на стенді не виміряно).

Обмеження: переривання, що приходять під час idle, рахуються як idle, тож
`cpu` трохи занижене; `loop` включає переривання, що прийшли під час
проходу. Debug halt зупиняє лічильник.
