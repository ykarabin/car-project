# Радіо й Gateway

ESP32-S3-N16R8, ESP-IDF 6.0.1. Два джерела: ELRS (CRSF) або звичайний
PWM-приймач. Підключення — [hardware.md](../hardware.md#gateway-та-звязок-mcu),
збірка — [usage.md](../usage.md#збірка-й-запуск-gateway).

## Вибір джерела

Старт — `NONE`, команда ERROR з нульовими стіками. Вибирається джерело, що
першим дало валідні дані; при однаковому часі — ELRS. Активне джерело
тримається, поки валідне. При втраті Gateway шле щонайменше одну ERROR,
переходить у `NONE` і знову вибирає перше валідне. Розраховано на один
увімкнений пульт за раз.

## ELRS: Happymodel ES900 Dual RX + RadioMaster TX15

ES900 — приймач 900 МГц. Підключення: `5V`, `GND`, `TX` приймача → GPIO16
(UART1 RX). UART 3,3 В, 420 000 бод, CRSF.

Налаштування пульта (EdgeTX, ExpressLRS 3.5.5 FCC915 на перевіреному TX15):

1. Окрема модель `Remote Gateway`, `Internal RF` → `CRSF`.
2. `Packet Rate` — `50 Low Band` (900 МГц, 50 Гц), `Switch Mode` — `Hybrid`.
3. Версії ExpressLRS пульта й приймача однієї основної гілки, діапазон
   приймача FCC915. Binding — однакова Binding Phrase у WebUI або вручну:
   тричі подати живлення на приймач (вимикаючи в межах 2 с після перших
   двох), на пульті `[Bind]` у ExpressLRS Lua.
4. Приймач: протокол `CRSF`, звичайна полярність, 420 000.
5. Mixes:

| Канал | Source | Weight | Призначення |
| --- | --- | --- | --- |
| CH1 | `Ail` | 100 % | кермо (правий стік, горизонталь, Mode 2) |
| CH2 | `Ele` | 100 % | вперед / назад (правий стік, вертикаль) |
| CH3 | трипозиційний перемикач, напр. `SC` | 100 % | режими 1 / 2 / 3 |
| CH5 | `MAX` | −100 % | стартовий стан disarmed для ELRS arming |

Outputs: межі ±100 %, subtrim 0, знаки перевірити через `Direction`.

Обробка CRSF (`crsf.c`, `elrs.c`):

- Адреси `0xC8` і `0x00`, кадр каналів `0x16`, CRC-8/DVB-S2.
- Діапазон перевіряється лише для каналів маски (CH1–CH3): на ES900
  невикористаний CH13 = 2047.
- Нормалізація 172 / 992 / 1811 → −1000 / 0 / +1000.
- Timeout 200 мс від останнього валідного кадру каналів. Failsafe типу cut
  припиняє кадри; затримка виявлення включає поведінку самого приймача.

## PWM-приймач

CH1 / CH2 / CH3 → GPIO5 / 6 / 7 через послідовні 2,2 кОм (сигнали 3,3 В).
MCPWM capture: один таймер, три канали, обидва фронти.

- Імпульс 800…2200 мкс, період 3…50 мс; валідність — після трьох коректних
  періодів на кожному каналі, timeout каналу 100 мс.
- Калібрування 1000 / 1500 / 2000 мкс; газ — до 1980 мкс
  (`sdkconfig.defaults`). Нейтральна зона ±20 мкс.
- CH3 — циклічний перемикач: кожна стабільна (40 мс) зміна рівня дає
  1 → 2 → 3 → 1. Після втрати й відновлення CH3 спершу задає базовий стан.
- Налаштування — `idf.py menuconfig` → `Remote Gateway PWM RC`.

Стенд 19.11.2026 (без резисторів до GND): канали стабільні, помилок 0;
CH1 1020–2010 мкс, CH2 990–1981 мкс; нейтраль ≈ 1515 / 1485 мкс дає 0.
Вимкнення живлення приймача → `ERROR / NONE`, відновлення без перезапуску.

**Обмеження:** якщо приймач після втрати радіо видає hold або failsafe PWM,
Gateway бачить валідні імпульси й ERROR не надсилає. На тесті з вимкненням
пульта саме так і було — failsafe PWM-приймача треба налаштувати окремо.
