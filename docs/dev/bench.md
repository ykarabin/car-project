# Стенд

Усі перевірки — на піднятому авто, колеса без навантаження.

## Порядок прошивання ECU

1. Вимкнути живлення моторів.
2. Зберегти 4 КБ калібрування (`0x0807F000`, 4096 байт) — через OpenOCD
   `dump_image` або [`tools/bench/openocd_rpc.py`](../../tools/bench/openocd_rpc.py).
3. Прошити ELF / HEX без повного стирання Flash, перевірити запис (`verify`).
4. Знову прочитати 4 КБ і порівняти з копією до прошивання (SHA-256).
5. Подати живлення моторів, пульт у нейтралі, перевірити RTT: калібрування
   завантажене (55 / 3612 / 552), `RC OK`, немає `MOTOR BLOCKED`.

Еталон калібрування — `.local/calibration-reference-55-3612-552.bin`
(локально, поза git).

## Сценарій перевірки

1. Старт: `RC WAITING` → після пульта в нейтралі `RC OK`, рух лише після нейтралі.
2. Режими 1 / 2 / 3 в обидва боки, `STAT` показує швидкість і PWM.
3. Реверс: перше «назад» гальмує; нейтраль і друге «назад» — задній хід;
   зупинка в нейтралі після руху вперед — «назад» відразу.
4. Кермо: стік ↔ положення, відпускання → `STEER_RELEASE CENTERED`, ручний поворот.
5. Вимкнення пульта в нейтралі: `REMOTE_ERROR` → `STALE`, руху немає;
   після ввімкнення — знову потрібна нейтраль.
6. Після тесту: калібрування незмінне, `fault=0`.

## Чекає перевірки

Зміни, перевірені лише хостовими тестами. Після перевірки — рядок у
«Результати», пункт звідси прибрати.

- [ ] **Gateway після правок 24.11** (форматування, MISRA, `static` у функціях):
      ELRS і PWM-приймач дають `RC OK`, перемикання джерела, UART до ECU без
      нових помилок, режими CH3.
- [ ] **ECU після правок 24.11**: сценарій вище повністю (п. 1–6), парсер
      протоколу переписано (пошук `*` без `strchr`).
- [ ] **Заклинювання керма, REMOTE**: стік у бік, кермо втримати рукою →
      через ≈ 1 с `STEER_RELEASE STALL`, у `STAT` `STALLED`, кермо вільне; поки
      стік відхилений — не захоплюється; після нейтралі й нового відхилення —
      знову працює. Задній привід увесь час без змін.
- [ ] **Заклинювання під час центрування**: відпустити стік, утримати кермо
      рукою → `STALL` раніше за `TIMEOUT` (2 с).
- [ ] **Немає хибних STALL**: швидкі й повільні рухи стіком, кермо до упорів,
      колеса на покритті (з навантаженням). Якщо механізм під навантаженням
      повільний — збільшити `STEERING_CONTROL_STALL_TIMEOUT_MS` або зменшити
      `STALL_PROGRESS_COUNTS`.
- [ ] **Недохід до центру** (raw 69 / 72 при центрі 55): чим тепер
      закінчується — `CENTERED`, `STALL` чи `TIMEOUT`.
- [ ] **База продуктивності**: 5 хв у звичайній роботі (режими, кермо) і
      окремо в нейтралі — записати `PERF` (avg / max / jitter / cpu) у
      «Результати». Перевірити, що `loops` ≈ 5000 за вікно і `cpu` не 0.
- [ ] **SLP під час reset**: чи pull-down переважує pull-up Pololu md31c.
- [ ] **Failsafe PWM-приймача** при втраті радіо.
