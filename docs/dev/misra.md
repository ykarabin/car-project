# Статичний аналіз і MISRA C

Власний код (ECU, `shared/remote_protocol`, Gateway) перевіряється
`cppcheck` з аддоном MISRA C:2012, форматування — `clang-format`. Список
файлів — `tools/lint/sources.py`; CubeMX, HAL, CMSIS, FreeRTOS, SEGGER RTT,
ESP-IDF і дисплейний блок не перевіряються. Сертифікована відповідність MISRA
не заявляється: аддон перевіряє лише частину правил, текстів правил у
репозиторії немає (ліцензія MISRA), тож звіт містить лише номери.

## Як працює перевірка

```sh
tools/lint/check.py format            # --fix переписує файли
tools/lint/check.py cppcheck          # потрібен build/compile_commands.json Gateway
```

- **Загальні перевірки** cppcheck (`warning`, `style`, `performance`,
  `portability`) мають бути порожні. Обґрунтований виняток — лише в коді,
  `/* cppcheck-suppress <id> */` з поясненням поруч.
- **MISRA** порівнюється з базою `tools/lint/misra-baseline.json`: кількість
  знахідок на правило й файл. Більше — помилка, менше — помилка з проханням
  зменшити базу (`--update-baseline`) і закомітити її. База лише зменшується.
- **Відхилення на весь проєкт** нижче в базу не входять.

Версії зафіксовані: cppcheck 2.22, clang-format 23.1. Інша версія дає
попередження, бо набір знахідок може відрізнятися.

## Відхилення на весь проєкт

| Правило | Суть | Чому відхиляємось |
| --- | --- | --- |
| 15.5 | одна точка виходу | Ранні `return` для перевірки входу, аварійних виходів і таблиць назв станів — видно порядок перевірок, менше вкладеності. Рішення 18.11.2026 ([README](README.md)). |
| 8.7 | внутрішнє зв'язування, якщо функцію викликає один файл | Інтерфейси модулів (`wheel_speed_*`, `steering_controller_*`, `remote_parser_*` …) викликаються з одного файлу прошивки, але є API модуля й тестуються хостовими тестами. |
| 17.1 | `<stdarg.h>` | Лише в `debug_console_printf_at`: форматування рядків RTT. Логіка керування не використовує. |
| 21.6 | `<stdio.h>` | Лише `snprintf` / `vsnprintf` з розміром буфера: діагностика RTT і текстовий кадр UART-протоколу. Результат перевіряється (від'ємний, обрізаний). |
| 19.2 | `union` | `vehicle_log_message_t.data`: поле вибирає `kind`, читається лише відповідне поле. Економить RAM черги логів. |

## Поточна база

24.11.2026 знахідки у власному коді виправлено одним проходом (124 → 18).
ECU і `shared/remote_protocol` — без знахідок. Усі 18, що лишились, — у
рядках з макросами ESP-IDF, які не переписуються:

| Правило | Звідки |
| --- | --- |
| 10.1, 10.4 | `ESP_LOGI` / `ESP_LOGW`, `GPIO_IS_VALID_GPIO`, `GPIO_IS_VALID_OUTPUT_GPIO` |
| 10.8 | `ESP_ERROR_CHECK` |
| 7.2 | `portMUX_INITIALIZER_UNLOCKED` |

Поодинокі обґрунтовані винятки в коді позначені
`/* cppcheck-suppress … */` з поясненням поруч: `void *context` у callback
захоплення PWM (`pwm_rc.c`, сигнатура задана ESP-IDF).

Перевірка виправлень: 39 хостових тестів (34 ECU, 5 Gateway); машинний код ECU (Release) порівняно
по функціях з попередньою версією — змінилась лише `remote_parser_push`
(пошук `*` циклом замість `strchr`), решта побайтно та сама.
