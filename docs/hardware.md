# Підключення та інтерфейси

## Склад системи

- ESP32-S3 із Flash 16 МБ — Gateway радіопульта.
- WeAct STM32G473VET6 — ECU.
- Два задні двигуни WM4853, 24 В; двигун керма DL 555-C, 24 В.
- Три драйвери Pololu G2 24v13, сигнали PWM/DIR/SLP/FLT.
- RIGHT MT6826S — квадратурний енкодер швидкості; MT6701 — положення керма.
- Кнопка PC13 та LED PF2 плати WeAct.

Логічні сигнали MCU — 3,3 В. Перепідключення виконувати без живлення.
Живлення двигунів і логічних плат визначається їхніми окремими вимогами;
інтерфейси мають спільний сигналовий GND.

## Рівні сигналів і живлення

| Вузол | Живлення | Сигнали до MCU |
| --- | --- | --- |
| ESP32-S3 GPIO | 3,3 В | 3,3 В; входи не толерантні до 5 В |
| ELRS-приймач → ESP32 GPIO16 | за вимогами приймача | UART TX 3,3 В |
| PWM RC-приймач → ESP32 GPIO5/6/7 | 5 В | 5 В → дільник 2,2 / 3,3 кОм → ≈3,0 В |
| ESP32 UART2 TX → STM32 PD6 | — | 3,3 В |
| MT6826S (RIGHT) → TIM3 | 3,3 В | A/B 3,3 В |
| MT6701 → TIM4 | 3,3 В | PWM 3,3 В, ≈501,5 Гц |
| STM32 → Pololu G2 (PWM, DIR, SLP) | — | 3,3 В логіка STM32 |
| Pololu G2 FLT → STM32 | — | active LOW, 3,3 В |
| Pololu G2 VIN, двигуни | 24 В (діапазон драйвера 6,5–40 В, 40 В — абсолютний максимум) | — |
| Кнопка PC13, LED PF2 | 3,3 В плати WeAct | active HIGH |

## Gateway та зв'язок MCU

| Сигнал | Підключення |
| --- | --- |
| ELRS/CRSF TX приймача | ESP32 GPIO16, UART1 RX |
| PWM RC CH1 / CH2 / CH3 | ESP32 GPIO5 / GPIO6 / GPIO7 |
| Команди Gateway → ECU | ESP32 GPIO4, UART2 TX → STM32 PD6, USART2 RX |
| Спільний GND | GND Gateway ↔ GND ECU ↔ сигналовий GND приймача |

Використовується ELRS або альтернативний PWM-приймач. Входи ESP32 не
призначені для безпосереднього подавання 5-вольтових сигналів.
PWM-приймач має живлення та сигнали 5 В, тому кожен канал CH1/CH2/CH3
підключений через резистивний дільник: 2,2 кОм послідовно від виходу
приймача, 3,3 кОм від входу ESP32 до GND. На вході ESP32 це
5 × 3,3 / (2,2 + 3,3) ≈ 3,0 В, що вище порогу логічної одиниці
(0,75 × 3,3 ≈ 2,5 В). Внутрішній pull-down GPIO підключений паралельно
3,3 кОм і на рівень практично не впливає.

PWM capture перевіряє імпульси 800…2200 мкс і періоди 3…50 мс;
базове калібрування 1000/1500/2000 мкс відповідає −1000/0/+1000.
Канал газу CH2 має окремі межі: у поточній конфігурації 1000/1500/1980 мкс.
Gateway масштабує їх до −1000/0/+1000; інверсія застосовується після
масштабування. Калібрування керма та режимів від цього не змінюється.
Якщо приймач після втрати радіозв'язку продовжує видавати коректний hold
або failsafe PWM, Gateway бачить валідні імпульси.

## ECU: двигуни та датчики

| Вузол | Сигнали STM32 |
| --- | --- |
| Лівий задній драйвер | PWM PA8/TIM1_CH1, DIR PD14, SLP PD8, FLT PD11 |
| Правий задній драйвер | PWM PA9/TIM1_CH2, DIR PD15, SLP PD9, FLT PD12 |
| Драйвер керма | PWM PA10/TIM1_CH3, DIR PB14, SLP PD10, FLT PD13 |
| RIGHT MT6826S | A PB4/TIM3_CH1, B PB5/TIM3_CH2 |
| MT6701 | PWM PB6/TIM4_CH1 |
| Кнопка калібрування | PC13, active HIGH, pull-down |
| LED кроку калібрування | PF2, active HIGH |
| Діагностика | SWD через ST-Link, RTT up channel 0 |

TIM1 генерує PWM 20 кГц. DIR задає напрямок, SLP HIGH дозволяє драйвер.
SLP HIGH із PWM=0 — електричне гальмування; SLP LOW — coast/Hi-Z.
FLT active LOW використовує EXTI. LOW, підтверджений протягом 2 мс,
або 3 спадні фронти за будь-яку 1 с на одному драйвері вимикають усі
драйвери до reset. Поодинокі короткі імпульси допускаються; будь-який LOW
перед пробудженням забороняє піднімати SLP. Короткі імпульси в межах 2 мс
після зміни SLP не враховуються в ліміті серії; перевірка тривалого LOW
залишається активною і під час переходів.

RIGHT: 4096 counts на оберт вала двигуна, редуктор 1:20, діаметр
колеса 29 см, вікно вимірювання 10 мс. TIM3 — 16-бітний; wrap враховується.
MT6701 декодується як абсолютний raw 0…4095 через PWM input capture.
TIM6 працює як HAL tick і мікросекундна основа часу; його не переналаштовує
прикладна логіка регуляторів.

LEFT/TIM2, обидва Z і ADC1/CS/DMA залишені в CubeMX як зарезервовані
підключення; прикладні вимірювання не запускаються, Z IRQ замасковані.
Повна конфігурація пінів — `firmware/vehicle-ecu/vehicle-ecu.ioc`.

## Протокол Gateway → ECU

UART: 115200 baud, 8N1, один рядок кожні 20 мс:

```text
RC,-321,654,2,0,42*C6DA\n
```

| Поле | Значення |
| --- | --- |
| `RC` | Тип команди |
| `steering`, `throttle` | Цілі значення −1000…+1000 |
| `mode` | 1, 2 або 3 |
| `status` | 0 OK; 1 ERROR з нульовими стіками |
| `sequence` | 0…255 із циклічним переходом |
| `CRC` | CRC-16/CCITT-FALSE тексту перед `*`, чотири hex-цифри |
| `\n` | Кінець рядка LF; парсер також приймає CRLF |

Поля перевіряються до застосування. Буфер рядка — 64 байти; завеликі
рядки відкидаються. Комунікація одностороння, підтвердження від ECU немає.

## Зберігання калібрування

Останні 4 КБ Flash STM32 (`0x0807F000…0x0807FFFF`) зарезервовані linker
script і не містять firmware image. Дві сторінки зберігають записи
калібрування з CRC, sequence та commit-маркерами. Калібрування містить
фізично визначений центр і ліву/праву межі механізму.
